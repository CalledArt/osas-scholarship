# Views Admin

## The admin welcome banner departs from DESIGN.md on purpose
Decided 2026-10-24: the admin dashboard header is a welcome banner drawn to the mock OSAS supplied: rounded-lg mint panel (seal-wash #EEF7F3, seal-tint border), graduation-cap icon in a round seal-tint disc, "Welcome back, {full_name}!" as the h1, the live status sentence under it, and "+ Post scholarship" on the right. OSAS asked for the "View all" link to stay outside the banner; it now heads the postings table below. The page runs at max-w-[100rem] (widened from 88rem on 2026-10-25 to match the student dashboard), so a 1920px screen is filled beside the rail instead of left as empty gutters. It deliberately breaks DESIGN.md's True Corner and colour rules. It lives in x-welcome-banner (the status sentence is its slot, the button its `action` slot), which the student dashboard, Scholarships and My Applications pages and the admin Scholarships, Fund Allocation, Search Student and Edit Student Data pages (list and edit form) also use since 2026-10-25 at the user's request (its `heading` prop carries each page's h1). seal-wash exists only for this banner. Don't square it off or reuse seal-wash elsewhere without asking.

## Admin stat boxes: scholarships and students, no extra queries
Decided 2026-10-24: three x-stat-card boxes sit under the welcome banner, drawn to OSAS's mock (mint, blue and gold tints, round icon discs; blue is the only non-green/gold hue in the app and exists only here). Total scholarships splits into open (isOpenForApplications), ended (status Ended) and closed (everything else, including past deadline and full). "Students with Active status" (renamed from "Total active students" so it reads as the student status OSAS sets, not activity in the system) and "Students on leave of absence" count role=Student users by student_status. Staff rows also default to Active, so the role filter is required. Admin DashboardController reads the student counts as uncorrelated subqueries on its one scholarships query (like AppLayout's unread_total) and counts them directly only when no scholarship exists. Don't add a separate count query.

## The dashboard postings table lists the two newest
Decided 2026-10-24: below the stat boxes, "Recent scholarship postings" lists the 2 newest postings (DashboardController::RECENT_POSTINGS_LIMIT, cut from 5 at OSAS's request), newest first, drawn to OSAS's mock. When OSAS posts another, the oldest drops off the table. It is never deleted, and the Scholarships page ("View all") still lists it. It reuses the controller's one scholarships query ($postings), so it adds no round trip. Scholarships record no provider, so the mock's Provider column shows Type. Its only action is View; OSAS asked for no Edit there (edit from the scholarship's own page). Don't add a ⋮ menu either: a dropdown inside the table's overflow-x-auto would be clipped. Status reads Open / Closed / Ended the same way the stat box counts them. It always shows, with an empty row when nothing is posted. The "Ready for a pass list" and "Still taking applications" lists were both removed at OSAS's request. The banner's status sentence still counts them from the controller's readyForPassList / takingApplications. Don't bring the lists back unless asked. It replaced the old "View all N scholarships" link; its own "View all" goes to admin.scholarships.index.
